# 罗汉到家

罗汉到家是一个上门按摩 O2O 全栈 Web 原型，围绕“登录、查看附近技师、选择服务、预约下单、跟踪履约”完成用户端业务闭环。项目采用移动端优先设计，同时兼容桌面浏览器，适合作为全栈面试项目或产品 MVP 演示。

在线体验：[https://luohan-home-care-cn.surge.sh](https://luohan-home-care-cn.surge.sh)

## 核心功能

- 手机号演示验证码或密码登录、JWT 鉴权与退出登录
- 用户、技师、管理员三种角色及后端权限隔离
- 标签页级登录会话：刷新保持，关闭后重进需登录，失效 Token 自动返回登录页
- 附近技师列表和距离排序
- 技师头像、评分、成交量、价格及近期可约时间
- 从业年限由管理员维护；准时率无履约记录时为 100%，此后按到达记录自动计算
- 高德地图技师标记与本地地图降级
- 模拟技师移动和实时距离更新
- 服务项目、日期、时间、力度、地址和备注选择
- 预约档期按北京时间过滤过去时段，并根据真实订单占用显示“已约满”
- 每位技师拥有独立接单星期和工作时段；管理员可维护排班，前后端共同阻止休息日、非工作时间和同一技师重复占用
- 模拟支付、数据库订单与订单成功页面
- 六阶段订单状态展示、合法状态流转与手动推进
- 用户与技师位置、动态路线和预计到达时间
- 按摩偏好、积分、消费记录、历史订单和再次预约
- 技师接单履约工作台
- 管理员经营看板、订单管理、用户管理和技师新增／编辑／上下线／归档／恢复管理；归档保留历史订单并停止接单
- 管理员本地选择技师头像、自动裁切压缩（100 KB 内），以及服务项目新增／上下架与技师分配
- Toast、弹窗、选中态、加载态和页面切换动画

## 技术栈

- React 19：组件化页面和动态状态管理
- TypeScript：为技师、服务、预约和订单定义类型
- Vite：开发服务器与生产构建
- 原生 CSS：响应式布局、移动端交互和动画
- 高德地图 JS API：在中国大陆展示地图和位置标记
- Node.js + Express：模块化 HTTP 后端
- Prisma + SQLite：持久化用户、技师、服务、订单和积分数据
- JWT + Zod：登录鉴权和请求参数校验
- LocalStorage：后端离线时保留可演示的降级数据
- Mock 定时器：模拟技师移动和订单履约
- Surge：发布公开 HTTPS 演示链接
- CloudBase 免费体验环境：云函数 HTTP API + PostgreSQL，共享演示数据

## 高德地图配置

复制示例环境文件：

```bash
copy .env.example .env
```

在 `.env` 中填写自己的高德 Web JS API 配置：

```env
VITE_AMAP_KEY=your_amap_web_key
VITE_AMAP_SECURITY_CODE=your_amap_security_code
```

`.env` 已加入 Git 忽略列表，不会提交到仓库。生产使用时还应在高德控制台限制允许调用的域名。

如果没有配置高德地图，项目会自动显示本地 SVG 动态地图，核心预约和订单流程仍然可以正常演示。

## 原型说明

公开 Surge 页面已连接 CloudBase 云函数 HTTP API 与 PostgreSQL 示例数据库。用户、技师、管理员登录及订单／技师管理可跨设备共享；本地开发仍可使用 Express + Prisma + SQLite。云函数代码在 `cloudfunctions/luohan-api/`，配置在 `cloudbaserc.json`。服务端 API Key 和 JWT 密钥仅放在云函数环境变量中，不进入前端构建包。

目前坚持免费：Surge 使用 Free 套餐，CloudBase 使用免费体验环境，不升级付费套餐；资源点用尽时云端服务可能暂停，不能保证无限访问。演示管理员账号可修改共享样例数据，仅用于面试，勿存入真实客户资料。支付、短信、消息、定位和订单派发仍为演示实现，不产生真实交易。

新增技师必须上传头像，接受 JPG／PNG／WebP 原图（不超过 2 MB，至少 160×160 像素）；浏览器会裁切为 320×320 并压缩至 100 KB 内，后端再次验证必填、大小和格式。当前面试原型将压缩头像直接存入技师记录，便于保持免费部署；如果未来需要大量技师或高清相册，应迁移至对象存储并使用缩略图 URL。
