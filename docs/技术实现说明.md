# 罗汉到家技术实现说明

## 1 产品目标

罗汉到家是一款上门按摩和推拿 O2O 原型。MVP 重点验证用户能否快速找到附近技师、完成预约，并在下单后清楚掌握履约状态。

核心流程如下：

1. 登录并进入首页。
2. 查看附近技师和地图位置。
3. 进入技师详情，选择服务和可约时段。
4. 选择未来三天内的日期和时间，填写地址、力度及备注。
5. 完成模拟支付并生成订单。
6. 在订单页查看技师位置、路线、预计到达时间和六阶段状态。
7. 在我的页面查看偏好、积分、消费记录和历史订单。

## 2 前端架构

项目采用 React 单页应用结构。`App.tsx` 管理当前页面、登录状态、技师、预约草稿和订单对象，各业务页面拆分为独立组件，并通过属性和回调传递数据。

主要页面包括：

- `LoginScreen`：模拟用户登录。
- `HomeScreen`：技师列表、地图和首页功能入口。
- `TechnicianDetail`：技师介绍、服务项目和可约时间。
- `BookingScreen`：日期、时间、地址、力度及备注表单。
- `PaymentScreen`：优惠和模拟支付。
- `SuccessScreen`：下单成功结果。
- `OrdersScreen`：订单时间轴、状态操作和地图追踪。
- `ProfileScreen`：按摩偏好、积分、消费记录和历史订单。

## 3 技术选型

### React 19

React 用于拆分业务组件并管理高频动态状态。技师移动、距离变化、表单选择、Toast 和订单状态推进都可以通过状态更新驱动界面同步变化。

### TypeScript

TypeScript 为 `Technician`、`Service`、`Address`、`Order` 和页面状态提供类型约束，降低多页面传递数据时出现字段错误的概率。

### Vite

Vite 提供快速开发服务器、热更新和静态生产构建，适合快速开发并部署无后端原型。

### 原生 CSS

项目使用原生 CSS 实现移动端优先布局、桌面展示壳、底部导航、弹窗、Toast、按钮状态和页面动画。未引入大型 UI 框架，可以更直接地控制界面效果和包体大小。

### 高德地图和本地地图降级

高德地图适合中国大陆网络环境。应用通过环境变量读取 Key 和 securityJsCode，不在仓库中保存真实配置。

页面同时提供本地 SVG 地图。高德 SDK 加载失败、超时或鉴权异常时，本地地图继续展示用户位置、技师位置和路线，避免演示区域空白。

### LocalStorage

登录状态和订单使用 LocalStorage 保存，页面刷新后可以恢复演示数据。它适合无需后端的 MVP，但不能替代正式的账号系统和数据库。

### Mock 数据和定时器

技师与服务来自本地数据。定时器每隔约 2.2 秒轻微修改技师经纬度，列表距离、地图标记和路线会随 React 状态同步更新。

## 4 订单状态设计

订单使用数字索引表示六个履约阶段：

```ts
export const orderStatuses = [
  '待接单',
  '已接单',
  '已出发',
  '已到达',
  '服务中',
  '已完成',
]
```

订单页面根据状态索引更新：

- 当前阶段和时间轴样式
- 主要按钮文案
- 技师位置和预计到达时间
- 可执行的联系、取消或推进操作

这种方式适合原型演示。正式系统应由服务端维护状态，并通过 WebSocket 或 SSE 推送变化。

## 5 交互反馈

项目为主要操作提供至少一种可见反馈：

- 服务、时段和偏好具有选中状态。
- 收藏、联系、取消订单等操作返回 Toast 或弹窗。
- 按钮具有按压效果。
- 页面切换优先使用 View Transitions API。
- 浏览器不支持新 API 时自动使用普通切换。

构建前还会运行两个自定义检查脚本，扫描按钮反馈和状态交互，减少出现“按钮能点但没有反应”的问题。

## 6 中国大陆访问考虑

- 技师头像保存在项目本地，减少外部图片加载失败。
- 地图优先使用高德地图，不依赖国外地图瓦片。
- 高德异常时自动显示本地地图。
- 演示站使用 HTTPS，满足浏览器定位接口的基础要求。
- 正式上线建议使用国内云对象存储、CDN 和已备案域名。

## 7 当前限制

- 登录和支付均为前端模拟。
- 订单只保存在当前浏览器。
- 技师移动为定时器模拟。
- 消息页面未接入即时通信服务。
- 没有用户、技师、管理员三类服务端权限。

## 8 生产化升级

1. 建立服务端鉴权和角色权限系统。
2. 建立用户、技师、服务、排班、订单、优惠券和积分数据表。
3. 使用 REST 或 GraphQL API 替换 Mock 数据。
4. 使用 WebSocket 或 SSE 推送接单、位置和服务状态。
5. 接入微信支付或支付宝，并处理回调和退款。
6. 接入真实定位、逆地理编码、路线规划和服务范围校验。
7. 增加自动化测试、日志、监控、告警和持续部署。
